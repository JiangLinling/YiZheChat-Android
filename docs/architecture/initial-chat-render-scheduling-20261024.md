# 聊天首次正文读取的有界调度

状态：源码及相关本地回归已接通；最终冻结包和双机验收尚未完成。本文不是发布或验收证明。

## 责任和边界

本变更沿用 LC02 的会话导航、LC13 的正文读取和现有 Matrix、KMS 调度组件，不增加生命周期、工作队列或并发池。
`FOREGROUND_BOOTSTRAP` 仅表示用户当前打开聊天的有限首屏需求，不表示消息已显示、已读或已获得正文授权。
它是 Android 进程内调度分类，不序列化到 KMS，不改变 iOS 或既有服务器协议。

Matrix 仍负责原始事件身份，Android 负责真实窗口可见事实，KMS、Vault、策略和现有读取流程负责授权。
`readPurpose`、原 `operationId`、nonce、内容版本、scope owner、授权 revision 和消费前复核均保持原样。
不同生命周期操作不能因提速而合成一个 HTTP 上下文；同一操作仍依原顺序处理。

## 进入、激活和退休

只有当前用户可见的 live timeline 测量入口可以请求首屏调度，旧调用和后台订阅默认不启用。
初次 `false/empty` 或尚未测量不代表退出：此时尚未激活，不分配首屏优先级。
第一次含有效非空候选的前台测量只锁定一次原始身份集合，最多取原尾部 30 项，此后只缩小，不能由新增事件或授权重试补充。
只有锚点、候选仍为空的初始投影继续保持 UNARMED；不以空 Map 消耗这一次有效集合捕获机会。

资格要求最后一个实际可显示的真实事件位于测量窗口内；其后的每个真实事件必须属于上述集合，
并被现有解析确认是普通、非阅后即焚、空安全壳的 `DECRYPTING` 文字。只可跳过纯 Virtual 项。
未知、隐藏操作、附件、终态或映射不一致不能当作空白跨越；没有真实锚点时保留原历史路径。
普通文字的元数据还须来自 canonical remote 事件、TEXT 信封和 FOLLOW_ROOM 生命周期。
这些条件只决定调度，信封内容和当前授权仍须经过原流程校验。

激活后离开渲染尾部、用户不可见或 owning scope 退出，会永久退休本次进入的未派发资格。
KMS 按相同 owner 和递增 viewport generation 接收该有限集合；旧代、错 owner、ROOM_PREVIEW 和未提示请求不能提升。
已派发请求不重派、不换 nonce、不提前清除 HTTP 所有的字节；迟到结果继续经过原 stale gate 和清零路径。
普通 DECRYPTING 正文仍不可见，不增加明文持久化或缓存范围。

## 三层资源限制

Matrix 和 KMS timeline 都复用原有 3 个前台 worker 和 1 个历史 worker。
其中最多 2 个前台 worker 可以借给首屏读取，另 1 个只接真实测量可见任务；历史 worker 的既有职责不变。
独立的有界唤醒信号只通知原队列有可选任务，避免只处理可见项的 worker 吃掉首屏任务的唤醒。
尚未测量的 owned generation-zero 读取诚实使用 HISTORY_PREFETCH，只由原历史 worker 派发。
三个前台 worker 都不能提前等待不可升级的 generation-zero 历史票据。
完成真实测量后，其中两个才可处理有限首屏集合，另一个继续只处理真实可见任务。
全隐藏会话仍由原历史 worker 读出第一条授权锚点，不等待测量形成循环依赖。

物理 HTTP 总数仍最多 4；普通 BACKGROUND 最多 1，BOOTSTRAP 最多 2，全部非 CURRENT_MESSAGE 合计最多 3。
真实可见消息在借用 worker 中先于待处理首屏项；原可靠工作和历史公平性保留。
首屏不能消费真实前台的待处理位置预留，共享读取 registry 也继续把它计入非 visible 限额。

## 核对方式和当前限制

相关回归覆盖首次 inactive→active→inactive→active、逻辑渲染尾部、全隐藏首锚点、晚到测量、
阻塞历史和两个独立首屏操作时的真实可见任务、4/2/1 上限、操作顺序、预留容量、preview 和 owner 隔离。
共享读取、授权上下文、原接收生命周期、投影及聊天界面接线也运行相关回归。
实际效果仍须由同一正常 Release APK 的 13、10S 首次和重复聊天窗口、基本通信及 scope 恢复验收确认。
先前 73、74、75 包的首次历史投影均未通过，不得由本地回归通过推断已解决或已发布。
74 的两台真机重复进入和 QA74 草稿输入正常，但首次进入仍有普通历史分批出现；该包未发布。
后续本地复现确认：先启动 worker、后测量 viewport 时，两个可借用 worker 提前派发 HISTORY，
导致首屏集合即使有效也没有空闲借用位置。回归须在旧历史 gate 仍阻塞时观测两个独立 BOOTSTRAP，
同时让新实际可见项通过保留位置；总 worker 和 HTTP 上限、已派发票据、授权及身份判断均不变。
75 真机首次展示仍未通过；本地另复现出先锚点-only、后同 scope 初始 Reset 补齐文字时的空捕获问题。
修正只让空候选保留 null；一旦捕获非空集合仍不补充，Reset 后相同 eventId 也不能替代原始对象身份。
本地 189 项相关回归通过不代表该问题已被证明是真机全部根因，下一候选仍须双机验收。

## 76 未通过后的最小只读观察

76 的正常双机首次窗口仍显示迟到历史，因此停止根据局部假设连续修改，先观察实际分支。
本轮仅补 LC-23 的非持久匿名计数，观察 LC-02/LC-13；不修改授权、密钥、生命周期、排队或显示资格。
每个原 scope 的观察对象只接收 enum/int/bool；仅真实非空测量窗口可选择当前观察 owner。
摘要固定最多 16 条不可变状态，保留前 4 条及最近 12 条；计数有界，不存任何原始对象或标识。
内容包括现有分支已算出的 raw/shell/有限集合数量、raw 引用匹配数、尾部拒绝枚举、初始 Reset 和 Matrix 派发计数。
Matrix 派发不等于物理 HTTP 已发出；本地摘要与录屏也不宣称精确同钟时延。

正常内测包可主动经 Android 既有 Activity.dump 请求专用参数 `--yizhe-initial-render-metadata`。
该分支仅写已有系统请求的输出流后返回，不调用 super.dump，不输出原始 prefix/args，不新增权限、组件或外部接口。
未知参数保留原有 dump 行为；识别到专用选择器但额外参数、非内测包或受保护前台不可见时，只返回 UNAVAILABLE。
读路径只读已捕获快照，不拿 Processor 锁、不查 Room/Vault、不解析信封、不发 KMS、不改变队列或清状态。
用户不可见时隐藏摘要，scope/账号退出及 hard authorization invalidation 清理；旧 owner 不能清除新 owner。
Release 的 debug/profileable/tracing/logcat/崩溃附件限制保持；不生成日志文件、不写磁盘、不发网络或加入 bug report。
这里没有恢复生产明文日志；若未来要持久诊断，仍须另行遵守 Log Key、脱敏和加密轮换合同。

## 77 真机观察后的完成投影等待修正
