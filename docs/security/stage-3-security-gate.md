# 第三阶段安全门槛

## 结论

第三阶段的 Android 与服务器代码闭环已经接通，但**尚未取得生产环境验收证据**。门禁已接到
`ContentProtectionService` 的加密和解密入口；Matrix 文本、位置和媒体收发映射、远端签名策略、设备证明/注册表、
DAK 短期 KMS proof、服务端 KMS v2、腾讯云 KMS CMK 包装和独立删除账本均有真实实现。生产 CMK/CAM、TLS pin、
管理员 mTLS、生产 APK 签名和双真机/旧备份恢复演练未配置时，门禁继续失败关闭。

这不是一个兼容性降级开关。条件不满足时必须拒绝发送/解密，不能退回普通 Matrix 消息或明文媒体。

## 已固化的门禁条件

每次加密和解密均验证：

1. 数据保护策略来自 `VERIFIED_REMOTE`，策略已生效、未到期，内容策略 ID/版本一致；
2. 内容有效期不超过远端策略有效期和内容保留截止时间；
3. 在线/有界离线模式与远端策略一致；
4. 远端策略至少要求 `TEE_OR_STRONGBOX`，本机硬件等级满足要求；
5. 安装身份与服务端信任结果一致，设备状态为 `TRUSTED`，不存在本地阻断风险；
6. 账号 Vault 已解锁；
7. DeviceShare 密钥属于当前安装身份，硬件等级与设备证明一致；
8. 发送时所有接收设备来自 Matrix 集成层提供的可信设备注册表；
9. KMS 使用 HTTPS、服务端签名公钥和至少一个证书固定值，禁止测试明文模式；
10. 当前会话能取得短期 KMS 授权；
11. Matrix 发送、接收、删除和备份恢复映射已由集成层声明为 `READY`。

任何条件失败都会抛出带稳定拒绝原因的 `StageThreeGateDenied`，便于管理端审计，但不会记录令牌、密钥或消息内容。

## 删除后不可恢复约束

`OfflineLicenseService.requireAccessAllowed` 现在位于**所有 KMS 释放之前**，包括 `ONLINE_REQUIRED`。删除协调器产生的
本地内容墓碑不再只保护离线许可证路径。因此，即使攻击者恢复删除前的 KMS 数据备份，本机仍会在请求 KMS 前拒绝该内容。

单元攻击演练覆盖：

1. 创建内容并保存旧 KMS share 备份；
2. 执行管理吊销，写入本地永久墓碑并删除 KMS share；
3. 将旧 KMS share 恢复回测试 KMS；
4. 解密必须得到 `Revoked`，且 KMS release 调用次数保持为零。

该测试证明的是客户端墓碑优先级，不替代服务器端恢复演练。卸载会删除应用私有墓碑；卸载后的最终防线仍必须是：

* Android Keystore 私钥随卸载失效，旧 DeviceShare 无法解封；
* 新安装获得新的 installation ID，旧设备注册不得自动恢复为 `TRUSTED`；
* KMS 的内容/设备吊销墓碑存放在与业务备份分离的不可回滚存储中；
* 恢复 Matrix 数据库、媒体仓库、Matrix Key Backup 和 KMS 业务备份后，KMS 仍拒绝旧安装和已删除内容。

## 不可解除的保护

无论生产项是否通过：

* `security.content_protection` 已标记完成并默认开启，缺少生产配置时必须失败关闭；
* Matrix binding 必须由实时 Matrix 客户端注册，不能伪造 `READY`；
* 不得将内置基线策略当作远端已验证策略；
* 不得通过捕获 `StageThreeGateDenied` 后发送普通 Matrix 消息来“保证可用性”。

编译和单元测试只能证明本地门禁行为，不能证明 KMS/HSM、设备注册、服务端备份和真实 Android 运行环境已经验收。
