# 管理端控制计划实现

## 边界

管理控制面是独立于 Matrix、ntfy 和 MindOrigin 的安全服务。它只处理策略、设备证明元数据、设备心跳、远程命令状态和不含正文的审计，不保存聊天正文、附件、密钥或访问令牌。

控制端不得关闭 Android 端已有的 Vault、敏感文件、数据库和内容信封加密。即使控制面未配置、临时不可用或返回无效签名，客户端仍保留本地安全基线。

## 已接入能力

| 管理能力 | 服务端 | Android 客户端 |
| --- | --- | --- |
| 数据保留和最大离线时间 | 签名策略、版本、生效和到期时间 | 验签后原子持久化，失效后回到严格基线 |
| 通知内容等级 | `HIDDEN`、`SENDER_ONLY`、`CONTENT_ALLOWED` | 映射到数据保护策略 |
| 截屏、复制、导出、分享 | 策略开关 | 由已验证远程策略提供，不暴露基础加密开关 |
| 设备安全等级 | StrongBox 或 TEE 要求 | DAK、硬件等级和风险信号；缺少硬件证明链时拒绝提升为可信 |
| 设备清单与风险 | 心跳、最后在线、账号哈希、KMS 和证明状态 | DAK 签名上报，不发送账号明文 |
| 锁定、解锁、吊销、账号清除 | 每条命令独立签名和单调版本 | 持久命令箱、信任恢复、密钥销毁、删除协调器、重启后续跑 |
| 删除进度和重试 | 记录状态、进度、错误码 | 上报有限错误码；失败重试生成新 ID、新版本和新签名 |
| KMS 与设备证明 | 汇总状态和人工审批 | 上报状态；仅匹配当前证明版本才接受可信决定 |
| 安全审计 | 元数据白名单 | 不上报消息正文、密文、令牌、密码或密钥 |

## 信任与抗重放

1. 控制面首次启动生成独立的 ECDSA P-256 策略签名密钥。
2. APK 固定签名公钥 ID、DER 公钥和服务端 TLS 证书 pin。
3. 策略和命令使用规范 JSON 签名，并携带 schema、版本、生效和到期时间。
4. Android 只接受固定 key ID 的有效签名，拒绝版本回退和同版本替换。
5. 设备同步和命令报告由 Keystore DAK 签名，并带时间戳和一次性 nonce；服务端拒绝超时和重复 nonce。
6. 客户端在 `noBackupFilesDir` 原子保存最后有效策略和命令状态；无网络时继续使用尚未到期的最后有效策略。
7. 安全关键策略无效、到期或签名错误时，客户端采用严格本地基线；服务端没有关闭本地加密的字段。

远程命令的重试不是重新播放原签名。服务端会将失败命令标为 `SUPERSEDED`，签发新 ID 和更高版本，客户端因此既能重试又不破坏防重放约束。

## 远程命令语义

- `LOCK`：立即将设备置为 `STALE` 并锁定所有账号 Vault。
- `UNLOCK`：服务端停止投影 `STALE`，重新签发设备原有的 `TRUSTED` 或 `MANAGED` 决定，并以设备后续 DAK 签名心跳确认恢复完成；Vault 是否重新打开仍受本机 App 锁和硬件认证约束。
- `REVOKE`：将设备置为 `REVOKED`，销毁设备共享密钥和账号 Vault 密钥，排入持久删除队列；冷启动恢复清理后上报完成。
- `CLEAR_ACCOUNT`：只匹配服务端下发的账号 SHA-256 标识，销毁目标账号 Vault 密钥并执行该账号删除协调器。

密钥销毁先于文件清理，因此删除流程中断、设备重启或部分闪存块未被覆盖时，残留载体仍以不可用密钥保护。客户端只向服务端报告状态、百分比和有限错误码。

## 构建接入

控制面通过独立 TLS 子域发布后，从 `/v1/public/signing-key` 获取公钥信息，并在私有 Gradle 属性中配置：

```properties
yizhe.control.baseUrl=https://control.example.invalid
yizhe.control.signingKeyDerB64=<subject-public-key-info-der-base64>
yizhe.control.signingKeyId=<sha256-derived-key-id>
yizhe.control.certificatePin=sha256/<certificate-spki-pin>
```

这些值不应提交到公共仓库。四项全部有效且 URL 为 HTTPS 时控制连接才会启用；任何缺项都会保持本地基线而不连接不完整的控制面。

## 部署隔离

`server/control-plane/compose.yaml` 使用独立项目名、容器、网络、卷和回环端口 `127.0.0.1:8790`。生产部署必须使用 YiZheChat 独立目录和子域，不复用、重启或修改 MindOrigin 的容器、网络、卷、数据库和反向代理站点。

初始设备登记只验证挑战绑定、证据签名和证书载荷，并保持 `PENDING`。上线批准前必须接入独立 Android Key Attestation 验证器，验证 Google 证明根、证明扩展、Verified Boot、应用包名和签名证书；没有该验证结果时不得批量自动批准设备。

## 验收清单

- 发布两个策略版本，确认客户端只接受较高版本并在离线时保留最后有效版本。
- 修改策略正文但复用旧版本，确认客户端拒绝。
- 重放相同设备 nonce，确认服务端返回冲突。
- 下发锁定、吊销和单账号清除，确认密钥销毁、重启续跑、最终状态和审计闭环。
- 制造可重试删除失败，确认新命令 ID、版本和签名，旧命令保持 `SUPERSEDED`。
- 断开控制面并超过最大离线时间，确认安全关键访问 fail-closed。
- 检查服务端数据库、日志和审计响应，确认不存在消息正文、附件、令牌、密钥或密码。
- 使用缺少硬件证明链、root、调试或应用签名异常的设备，确认不能被提升为可信。
