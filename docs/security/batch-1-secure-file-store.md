## 状态

`SensitiveFileStore` 已实现并进入 App Metro 图，状态为 `CONNECTED`。它提供真实的持久密文、流式读写、完整性验证、原子发布、对象删除、Vault 密码学擦除和失败恢复清理。

批次 2 已将 `security.secure_file_store` 默认打开并接入接收媒体；批次 5 已完成不可降级 cutover。上传预处理、拍照及编辑暂存的启动遗留会被清除，但运行时管道仍未加密；底座完成不等于全部业务载体已经受保护。

## 密钥和格式

每次写入生成独立随机 AES-256 对象密钥（DEK）。批次 6 起，每账号随机 AVK 由不可导出的设备根密钥（DRK）包装，DEK 再由 AVK 使用随机 AES-GCM nonce 包装，形成 `DRK -> AVK -> DEK` 层级。批次 1 历史对象使用的“每账号直接 Keystore 包装”格式仍可读取，并在首次成功读取后原子迁移为新信封；新写入不会再使用旧格式。

持久数据分为两份：

* `.yzsf`：只有版本化头、绑定摘要和分块密文；
* `.yzkey`：独立的 DEK 密钥信封，不包含业务明文。

文件名和目录只使用 Vault ID、对象 ID 的 SHA-256 结果以及随机信封 ID，不把 Matrix ID、账号或文件名直接暴露到路径。

格式版本为 1。正文按 64 KiB 分块使用 AES-256-GCM，每块 nonce 由随机文件前缀和单调块号组成。每块都绑定以下 AAD：

* 格式版本和块大小；
* 用途代码；
* Vault ID 摘要；
* 对象 ID 摘要；
* 调用方关联数据摘要；
* 密钥信封 ID；
* 块号和记录类型。

末尾存在独立 AEAD 终止记录，因此截断、拼接、换序、追加数据以及“调用方只读取前几个字节”的情况都会在 `read` 返回前完成全对象认证。

## 写入事务

写入顺序固定为：

1. 校验 opaque ID、关联数据和预期长度；
2. 检查 Vault 毁钥墓碑；
3. 生成随机 DEK、文件 nonce 和信封 ID；
4. 流式写入同目录 `.partial-*` 数据文件；
5. 写入终止认证记录并执行 `fsync`；
6. 写入并同步独立密钥信封临时文件；
7. 先原子发布 `.yzsf`，最后发布 `.yzkey`；
8. 任一步失败都删除临时文件；若只发布了数据，立即删除无信封密文。

密钥信封最后发布，保证崩溃最多留下不可解密的孤儿密文，不会留下可读取的半成品。

## 读取和篡改处理

读取时校验引用、路径、文件长度、格式版本、全部摘要、密钥信封和每个 AEAD 块。回调只读取部分数据时，存储层仍会在返回前继续验证到认证终止记录。

格式错误、截断、篡改、信封交换、引用不匹配和旧安装密钥缺失均 fail closed，不降级为明文读取，也不会静默忽略失败。

## 删除、卸载和恢复边界

单对象删除先删除 `.yzkey`，再删除 `.yzsf`。这能阻止正常 App 和普通文件恢复流程读取对象，但闪存原始取证同时恢复旧信封、且当前 Vault 包装密钥仍存活时，P1 不宣称单对象达到最终 KMS 级密码学撤销；该风险由后续 Vault 轮换和内容 KMS 批次关闭。

Vault 删除流程先写不可逆墓碑，再删除该账号的 AVK 信封和可能残留的旧版 Keystore 包装密钥，最后删除密文目录。只要 AVK 信封销毁成功，即使部分密文文件删除失败，也已经完成 Vault 范围密码学擦除。墓碑阻止同一安装重新创建同名 Vault 密钥。

持久根位于 `noBackupFilesDir`。卸载或清除数据后，安装标识、AVK 信封与 Android Keystore DRK 分别丢失；复制出的 `.yzsf/.yzkey/.yzvk` 无法由新安装密钥解密。真实设备上的卸载、换机和 Root 镜像仍属于后续取证验收，不以 JVM 单测替代。

## 自动恢复

`runMaintenance()` 清理：

* 失败或崩溃遗留的 `.partial-*`；
* 没有密钥信封的孤儿 `.yzsf`；
* 没有数据文件的孤儿 `.yzkey`。

路径始终限制在 `noBackupFilesDir/secure/v1` 内，拒绝路径穿越。

## 已验证

JVM 测试覆盖：

* 空文件和跨多个 64 KiB 块的二进制往返；
* 相同明文的随机化密文；
* 数据文件和信封文件中的 canary 明文扫描；
* 数据、终止记录、关联引用和密钥信封篡改；
* 回调只读取前缀时的全对象认证；
* 长度不符和写入异常不发布文件；
* 对象删除、Vault 毁钥墓碑和孤儿清理；
* 新安装密钥无法解密复制的旧容器；
* 旧版每账号 Keystore 信封成功读取后原子迁移到 DRK/AVK 信封。

仍需真机验证 Android Keystore 实际安全等级、OEM 行为、崩溃掉电、卸载重装和 Root 文件系统镜像。
