# 批次 4：删除协调器

## 实施结论

批次 4 已把账号级本地删除从一次性函数升级为可重入、可断电恢复的持久状态机。删除请求会在任何毁钥或删文件动作之前写入
`noBackupFilesDir/secure/v1/deletion-journal`；每个进度修订使用“新文件写入、`fsync`、重命名发布”，不覆盖当前有效记录。

账号退出和账号注销先在远端操作成功后、任何本地删行或删文件之前调用 `prepare`。然后停止客户端并向协调器确认：同步与界面已停止、活动
会话引用已释放、账号数据库已关闭。协调器随后负责：

1. 写入 `REQUESTED` 和调用方确认的前置步骤；
2. 写 Vault 墓碑、删除 Android Keystore Vault 包装密钥，并删除该 Vault 的加密对象和密钥信封；
3. 删除 SessionStore 凭据行，并只允许删除受管根目录下的两个随机 session 直接子目录；
4. 对仍打开的 App SQLCipher 数据库执行 WAL checkpoint/truncate；
5. 取消本 App 当前展示的全部系统通知；
6. 写入不含正文、令牌和密钥的完成审计；
7. 只有必需本地步骤全部成功后才发布 `COMPLETE`。

任一步失败都会保留错误码和待办记录。新进程在账号界面初始化前运行 `DeletionRecoveryInitializer`，此时尚未创建账号客户端，可安全确认
冷启动前置条件并重放所有未完成账号删除。即使进程死在 `prepare` 与关闭客户端之间，恢复流程也持有必要的 session 定位信息，可删除凭据
行和两个目录。操作 ID 已经完成时直接返回同一完成审计，不重复执行副作用。

## 持久格式和故障模型

持久记录只允许账号级删除，字段限于操作 ID、账号哈希、opaque Vault ID、本地 session ID、两个受管 session 路径、原因、策略版本、
时间、步骤、尝试次数和结果码。格式有固定
magic/version、字段边界、SHA-256 完整性校验和 16 KiB 上限。完成审计最多保留 128 条；卸载或清除数据会由系统删除整个 no-backup 私有目录。

进度采用不可变 revision 文件。进程在发布前死亡时继续使用上一修订；发布后死亡时使用新修订；最新修订损坏时会报告损坏数量并回退到
仍可验证的旧修订，所有已经完成的破坏性步骤都按幂等方式重做。损坏不会被静默当成成功。

## 完成边界

本批次完成的是“单设备、账号级、本地删除协调”：

* 已实现：持久任务、逐步提交、失败重试、启动续跑、SessionStore/受管目录删除、Vault 密码学擦除、加密文件删除、App 数据库维护、通知取消和有界非内容审计；
* 未实现：单消息/单媒体内容密钥索引，因此 `Content`/`Asset` 请求仍返回 `SCOPED_KEY_INDEX_NOT_AVAILABLE`，且不会制造一个永远假装可完成的任务；
* 未实现：KMS Share 删除、设备注册表吊销、服务器媒体和备份清理；`REVOKED_REMOTE_ACCESS` 必须在后续 KMS 批次接入，远端不可达不能反向阻塞本地毁钥；
* `PURGED_MEMORY` 表示 Rust 客户端、同步任务和活动会话引用已释放，不代表 Android/JVM 可以证明所有历史物理 RAM 单元已经覆零；
* `CANCELLED_NOTIFICATIONS` 会取消系统通知并由既有 SessionObserver 清理会话通知状态，但 OEM 通知历史和截屏等系统边界仍需 DLP/真机验收。

## 验收要求

自动化测试覆盖正常完成、数据库失败后恢复、通知失败后恢复、操作 ID 幂等、缺失前置条件失败关闭、拒绝 scoped 删除、进度跨实例恢复、
记录篡改检测和损坏修订回退。发布前仍必须在真机补齐：毁钥各步骤强杀进程、数据库 busy、断电/重启、低存储、通知历史、多账号、退出后
重新登录、卸载重装和文件系统镜像 canary 取证。编译和 JVM 测试不能替代这些运行验收。
